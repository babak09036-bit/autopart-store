# لوکس جوکر — فروشگاه اینترنتی لوازم جانبی خودرو

فروشگاه فارسی و راست‌چین با بک‌اند PHP 8.2 و MySQL/MariaDB، پنل مدیریت کامل، وبلاگ و ابزارهای سئو.
بدون فریم‌ورک (Laravel/Symfony/...) و بدون Node؛ رابط کاربری با HTML، CSS و JavaScript خام ساخته شده و Composer لازم نیست.

> شاخه `main` نسخه ایستای قبلی است که روی GitHub Pages منتشر شده. GitHub Pages کد PHP اجرا نمی‌کند؛ نسخه کامل (این شاخه) به هاست PHP نیاز دارد.

## امکانات

- **فروشگاه:** صفحه اصلی قابل مدیریت (۲۰ نوع سکشن)، فهرست محصولات با فیلتر و مرتب‌سازی، جستجو، صفحه محصول با تنوع و سازگاری خودرو، سبد خرید سمت سرور، کد تخفیف، ثبت سفارش، پیگیری سفارش، حساب کاربری، علاقه‌مندی‌ها و نظرات.
- **پنل مدیریت (`/admin`):** داشبورد و گزارش فروش با نمودار، محصولات و موجودی، دسته‌ها، برندها، خودروها، سفارش‌ها با تاریخچه وضعیت، مشتریان، کدهای تخفیف، مدیریت نظرات، پرسش‌ها، پیام‌ها، خبرنامه (خروجی CSV)، صفحه اصلی (کشیدن و رها کردن)، بنرها، منوها، صفحات، سوالات متداول، کتابخانه تصاویر، وبلاگ، سئو، ریدایرکت‌ها، سایت‌مپ و robots، تنظیمات، مدیران و نقش‌ها و گزارش فعالیت‌ها.
- **وبلاگ:** دسته، برچسب، نویسنده، فهرست مطالب خودکار، مقالات مرتبط، محصولات مرتبط، دیدگاه با تأیید مدیر، نسخه‌های قبلی، زمان‌بندی انتشار و پیش‌نمایش.
- **سئو:** عنوان، توضیحات، canonical، Open Graph و JSON-LD در HTML سمت سرور؛ آدرس‌های تمیز؛ ریدایرکت ۳۰۱ خودکار با تغییر اسلاگ؛ sitemap.xml بخش‌بندی‌شده؛ robots.txt قابل تنظیم؛ صفحه ۴۰۴ اختصاصی؛ noindex برای صفحات خصوصی و فیلترها؛ پیش‌نمایش نتیجه گوگل و تحلیلگر سئو در ویرایشگر.

## سازگاری قطعه با خودرو

- برند و مدل خودرو (با بازه سال تولید شمسی) در پنل، بخش «خودروها» تعریف می‌شود.
- در ویرایش محصول، تب «مشخصات، تنوع و سازگاری»، برای هر خودروی سازگار یک ردیف اضافه کنید: مدل، بازه سال (اختیاری؛ خالی یعنی همه سال‌های آن مدل) و توضیح (مثلاً «فقط موتور TU5»). کالاهای عمومی مثل روغن یا جاروبرقی را «مناسب همه خودروها» علامت بزنید.
- در صفحه محصول، مشتری خودرو و سال تولید را انتخاب می‌کند و پاسخ از سرور می‌آید: سازگار، سازگار نیست، فقط برای سال‌های دیگر، یا «اطلاعات سازگاری ثبت نشده». خودروی انتخاب‌شده در مرورگر مشتری ذخیره می‌شود. صفحه محصول بعد خودکار بررسی را انجام می‌دهد و در فهرست محصولات دکمه «فقط سازگار با خودروی من» دیده می‌شود.
- API: `GET /api/products?vehicle={slug مدل}&year={سال}` و `GET /api/products/{id}/fitment?vehicle=&year=`

اگر دیتابیس را پیش از اضافه شدن بازه سال ساخته‌اید، یک بار `database/migrations/001_fitment_years.sql` را اجرا کنید.

## نصب روی هاست

راهنمای گام‌به‌گام cPanel در [DEPLOY.md](DEPLOY.md) است. روی هاست بدون ترمینال، مدیر اصلی یک بار از `setup.php` ساخته می‌شود. این صفحه فقط با `SETUP_TOKEN` در `.env` و تا وقتی مدیری وجود ندارد کار می‌کند.

## رنگ‌بندی محصول

در ویرایش محصول، تب «مشخصات، تنوع و سازگاری»، برای هر تنوع گزینه «رنگ» را بزنید و رنگ را انتخاب کنید. اگر همه تنوع‌های یک محصول رنگ داشته باشند، در صفحه محصول به‌جای منوی کشویی، دایره‌های رنگ نمایش داده می‌شود. هر رنگ قیمت، SKU و موجودی جداگانه دارد و رنگ ناموجود خط می‌خورد. برای دیتابیس قدیمی‌تر، `database/migrations/003_variant_colors.sql` را یک بار اجرا کنید.

## تغییر گروهی قیمت و انبار

- **تغییر گروهی قیمت** (پنل ← فروشگاه ← تغییر گروهی قیمت؛ مجوز `pricing.bulk`): محصولات را با دسته‌بندی (همراه زیردسته‌ها)، برند و خودروی سازگار انتخاب کنید؛ شرط‌ها با هم ترکیب می‌شوند. افزایش یا کاهش درصدی یا مبلغ ثابت، روی قیمت اصلی، قیمت تخفیف‌دار یا هر دو، با گرد کردن به ۱۰۰، ۱٬۰۰۰ یا ۱۰٬۰۰۰ تومان و قیمت تنوع‌ها.
  - پیش از اعمال، پیش‌نمایش قیمت قبل و بعد نمایش داده می‌شود. محاسبه نهایی دوباره در سرور و در یک تراکنش انجام می‌شود.
  - قیمت کمتر از ۱٬۰۰۰ تومان اعمال نمی‌شود. اگر قیمت تخفیف‌دار از قیمت اصلی بیشتر شود، تخفیف برداشته می‌شود.
  - هر تغییر در «تاریخچه» ثبت می‌شود و قابل بازگردانی است. قیمت محصولی که بعد از آن دستی ویرایش شده دست نمی‌خورد.
- **انبار و موجودی** (مجوز `inventory.manage`): فهرست همه کالاهای قابل فروش (هر تنوع جداگانه) با فیلتر دسته، برند، خودرو و وضعیت (ناموجود، کم‌موجود). ویرایش موجودی و حد هشدار در همان ردیف (Enter ذخیره می‌کند). تغییر گروهی (افزودن، کسر، تنظیم، حد هشدار) به‌صورت همه یا هیچ. ارزش موجودی، خروجی CSV و «گردش انبار» با علت و انجام‌دهنده هر تغییر.

اگر دیتابیس را پیش از این بخش ساخته‌اید، یک بار `database/migrations/002_bulk_pricing.sql` را اجرا کنید.

## ساختار پوشه‌ها

```
index.php            ورودی صفحات فروشگاه (رندر سمت سرور)
api/index.php        ورودی REST API  (همه پاسخ‌ها: {success, message, data|errors})
admin/index.php      ورودی پنل مدیریت؛ admin/assets/ اسکریپت‌ها و استایل پنل
app/Core             هسته: روتر، درخواست/پاسخ، دیتابیس (PDO)، نشست، CSRF، احراز هویت، محدودسازی
app/Controllers      Api/ ، Admin/ ، Web/
app/Services         منطق کسب‌وکار: کاتالوگ، سبد، سفارش، پرداخت، نظرات، وبلاگ، سئو، آپلود، ...
app/Validators       اعتبارسنجی سمت سرور
app/Views            قالب‌های PHP صفحات فروشگاه و وبلاگ
config/  routes/     تنظیمات و مسیرها
database/            schema.sql، seed.sql و RELATIONSHIPS.md (نمودار روابط جدول‌ها)
bin/console.php      دستورهای خط فرمان
tests/run.php        تست عملیات حساس
storage/             لاگ، کش و فایل‌های خصوصی (خارج از دسترس وب)
uploads/             تصاویر بارگذاری‌شده (اجرای اسکریپت در آن غیرفعال است)
css/ js/ assets/     فایل‌های فرانت‌اند فروشگاه
```

پوشه‌های `app`، `config`، `routes`، `storage`، `database`، `bin`، `tests` و فایل‌های مخفی (مثل `.env`) با `.htaccess` از وب مسدود شده‌اند. روی سرور واقعی بهتر است این پوشه‌ها بیرون از document root باشند یا قانون معادل در تنظیمات وب‌سرور نوشته شود.

## پیش‌نیازها

- PHP 8.2 یا جدیدتر با افزونه‌های `pdo_mysql`، `mbstring`، `fileinfo`، `gd` و `json` (برای اجرای تست‌های HTTP: `curl`)
- MySQL 8 یا MariaDB 10.4 به بعد
- Apache با `mod_rewrite` و `AllowOverride All` (یا Nginx با قوانین معادل)

## نصب محلی (XAMPP)

۱. پروژه را در `C:\xampp\htdocs\auto` قرار دهید و Apache و MySQL را از XAMPP روشن کنید.

۲. دیتابیس و یک کاربر اختصاصی بسازید (رمز را خودتان انتخاب کنید):

```sql
CREATE DATABASE autopart CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'autopart'@'localhost' IDENTIFIED BY 'یک-رمز-قوی';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, DROP, REFERENCES ON autopart.* TO 'autopart'@'localhost';
```

۳. فایل تنظیمات را بسازید و مقادیر را پر کنید:

```bash
cp .env.example .env
```

برای اجرای محلی: `APP_ENV=local`، `APP_DEBUG=true`، `APP_URL=http://localhost/auto`، `SESSION_SECURE=false` و `PAYMENT_TEST_MODE=true`. برای `APP_KEY` یک رشته تصادفی بسازید:

```bash
php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"
```

۴. جدول‌ها و داده‌های اولیه را وارد کنید (فقط روی دیتابیس خالی اجرا می‌شود):

```bash
php bin/console.php db:install
```

یا دستی: ابتدا `database/schema.sql` و سپس `database/seed.sql` را در phpMyAdmin وارد کنید.

۵. اولین مدیر کل را بسازید. رمز عبور در دیتابیس اولیه وجود ندارد و همین‌جا از شما پرسیده می‌شود (حداقل ۱۲ کاراکتر، شامل حرف و عدد):

```bash
php bin/console.php admin:create
```

۶. سایت: `http://localhost/auto` — پنل مدیریت: `http://localhost/auto/admin`

## نصب روی هاست

۱. فایل‌ها را آپلود کنید. اگر هاست اجازه می‌دهد، document root را روی پوشه پروژه بگذارید و مطمئن شوید `.htaccess` فعال است.
۲. دیتابیس بسازید، `.env` را با این مقادیر تنظیم کنید و مراحل ۴ و ۵ بالا را از SSH اجرا کنید:

```
APP_ENV=production
APP_DEBUG=false
APP_URL=https://your-domain.ir
SESSION_SECURE=true
PAYMENT_TEST_MODE=false
```

۳. **HTTPS** را فعال کنید (مثلاً با Let's Encrypt از کنترل‌پنل هاست). کوکی نشست با `SESSION_SECURE=true` فقط روی HTTPS ارسال می‌شود.
۴. **دسترسی‌ها:** فقط `storage/` و `uploads/` باید برای PHP قابل نوشتن باشند (معمولاً `775` برای پوشه‌ها و `664` برای فایل‌ها). `.env` را با دسترسی `600` نگه دارید.
۵. **Cron** برای انتشار مقالات زمان‌بندی‌شده (هر ۵ دقیقه). مقالات زمان‌بندی‌شده در سایت هم با رسیدن زمانشان نمایش داده می‌شوند؛ این دستور وضعیتشان را در دیتابیس به‌روز می‌کند:

```
*/5 * * * * php /path/to/auto/bin/console.php blog:publish-scheduled
```

۶. **پشتیبان‌گیری:** روزانه از دیتابیس و پوشه `uploads/` نسخه پشتیبان بگیرید، مثلاً:

```bash
mysqldump --single-transaction autopart | gzip > backup-$(date +%F).sql.gz
```

### چک‌لیست پیش از انتشار

- `APP_DEBUG=false` و `APP_ENV=production` (در این حالت جزئیات خطا هرگز به کاربر نمایش داده نمی‌شود و فقط در `storage/logs` ثبت می‌شود)
- `PAYMENT_TEST_MODE=false` و اتصال درگاه واقعی (پایین‌تر)
- HTTPS فعال و `SESSION_SECURE=true`
- محتوای نمونه را جایگزین کنید: «نظرات مشتریان» صفحه اصلی با برچسب «نمونه نمایشی» مشخص شده‌اند و باید با نظر واقعی مشتریان (با اجازه خودشان) عوض یا حذف شوند. اطلاعات تماس و شبکه‌های اجتماعی را از «تنظیمات فروشگاه» به‌روز کنید.
- فایل `.env` و پوشه `storage/` هرگز در Git قرار نگیرند (در `.gitignore` هستند).

## پرداخت و ایمیل

- **پرداخت:** درگاه‌ها پشت رابط `App\Services\Payments\PaymentGatewayInterface` هستند. فقط درگاه آزمایشی (`TestGateway`) همراه پروژه است که هیچ پولی جابه‌جا نمی‌کند و فقط وقتی `PAYMENT_TEST_MODE=true` است فعال می‌شود. برای درگاه واقعی (زرین‌پال، IDPay، به‌پرداخت و ...) یک کلاس جدید با همین رابط بنویسید، کلیدهای آن را در `.env` بگذارید و در `PaymentService` ثبت کنید. تأیید نهایی پرداخت باید همیشه از سمت سرور و با استعلام از درگاه انجام شود.
- **ایمیل:** ارسال ایمیل پشت `App\Services\Mail\MailerInterface` است. درایور همراه پروژه (`log`) ایمیل‌ها را در `storage/logs/mail-*.log` می‌نویسد (مثلاً لینک بازیابی رمز). برای ارسال واقعی، یک درایور SMTP با همین رابط اضافه کنید.

## امنیت (خلاصه)

- همه کوئری‌ها با PDO و prepared statement؛ نام ستون‌های مرتب‌سازی فقط از فهرست مجاز.
- توکن CSRF برای همه درخواست‌های تغییردهنده (هدر `X-CSRF-Token`).
- خروجی‌ها escape می‌شوند و HTML محتوا (مقاله، صفحه، توضیح محصول) با فهرست مجاز تگ‌ها پاک‌سازی می‌شود.
- اعتبارسنجی سمت سرور برای همه ورودی‌ها؛ فقط فیلدهای تعریف‌شده ذخیره می‌شوند (جلوگیری از mass assignment).
- نقش‌ها و مجوزها در PHP بررسی می‌شوند، نه با مخفی کردن منو. اطلاعات تماس مشتری بدون مجوز «اطلاعات حساس» ماسک می‌شود.
- رمزها با `password_hash`؛ تعویض شناسه نشست پس از ورود؛ کوکی HttpOnly و SameSite (و Secure روی HTTPS)؛ قفل ورود پس از ۵ تلاش ناموفق در ۱۵ دقیقه؛ پایان نشست مدیر پس از ۲ ساعت بی‌فعالیتی.
- محدودسازی نرخ برای ورود، ثبت‌نام، سفارش، نظر، تماس و جستجو.
- آپلود: بررسی نوع واقعی فایل، بازسازی تصویر با GD، نام تصادفی، رد SVG و فایل‌های اجرایی، غیرفعال بودن اجرای اسکریپت در `uploads/`.
- قیمت نهایی، تخفیف و هزینه ارسال همیشه در سرور محاسبه می‌شود. ثبت سفارش در تراکنش با قفل موجودی و کلید `Idempotency-Key` انجام می‌شود و با خطا کامل برمی‌گردد.
- نشان «خریدار» فقط برای مشتری با سفارش تحویل‌شده؛ نظرات و دیدگاه‌ها فقط پس از تأیید مدیر نمایش داده می‌شوند.
- فعالیت‌های مهم مدیران (تغییر قیمت، موجودی، وضعیت سفارش، نظرات، تنظیمات و ...) در «گزارش فعالیت‌ها» ثبت می‌شود؛ رمز و توکن هرگز در لاگ نوشته نمی‌شود.

## تست‌ها

```bash
php tests/run.php
php tests/run.php http://localhost/auto
```

دستور اول فقط تست‌های واحد را اجرا می‌کند (پاک‌سازی HTML، اعتبارسنجی، آپلود، ریدایرکت). با آدرس سایت، تست‌های HTTP هم اجرا می‌شوند: هدرهای امنیتی، مسدود بودن فایل‌های حساس، CSRF، تزریق SQL، ثبت‌نام، سبد، سفارش تکراری با یک کلید، کم شدن موجودی، پرداخت آزمایشی، پیگیری و دسترسی به سفارش دیگران. برای مراحل مدیریتی (کد تخفیف، تغییر وضعیت سفارش، تأیید نظر و نشان خریدار) نام کاربری و رمز یک مدیر را در متغیرهای محیطی `ADMIN_USER` و `ADMIN_PASS` بدهید. تست‌های HTTP مشتری و سفارش آزمایشی می‌سازند؛ آن‌ها را فقط روی دیتابیس توسعه اجرا کنید.

## API

همه مسیرها زیر `/api` هستند. نمونه‌ها:

| مسیر | توضیح |
|---|---|
| `GET /api/products?cat=&brand=&min=&max=&sort=&page=` | فهرست محصولات با فیلتر |
| `GET /api/products/{id}` | جزئیات محصول |
| `GET/POST/PUT/DELETE /api/cart/...` | سبد خرید |
| `POST /api/orders` (هدر `Idempotency-Key`) | ثبت سفارش |
| `POST /api/orders/track` | پیگیری با شماره سفارش و موبایل |
| `GET /api/blog/posts` | مقالات |
| `/api/admin/...` | API پنل مدیریت (نیازمند ورود مدیر و مجوز) |

فهرست کامل در `routes/api.php` است.

## دستورهای خط فرمان

| دستور | کار |
|---|---|
| `php bin/console.php db:install` | وارد کردن schema و seed روی دیتابیس خالی |
| `php bin/console.php admin:create` | ساخت مدیر کل (رمز پرسیده می‌شود) |
| `php bin/console.php blog:publish-scheduled` | انتشار مقالات زمان‌بندی‌شده |

> داده‌های اولیه (محصولات، برندها، قیمت‌ها، مقالات) نمونه هستند. هیچ امتیاز یا نظر ساختگی برای محصولات ثبت نشده و GTIN محصولات خالی است تا بارکد واقعی وارد شود.
